# Interactive Lakehouse Dashboard

The platform includes a dedicated frontend built with Streamlit (`streamlit-dashboard`). It serves as the primary user interface for data exploration, model inference monitoring, and infrastructure health checks.

## Component Role

The dashboard operates purely as a presentation layer. It does not perform any heavy data processing or machine learning training itself. Instead, it delegates these tasks to the backend services (MinIO, PyArrow, FastAPI, MLflow) to ensure scalability and browser stability.

## Core Features

### 1. Bronze Layer Exploration (Real-Time PyArrow Pushdown)
- **Direct Data Lake Querying:** The dashboard connects to the Prediction API, which uses `pyarrow.dataset` to query the MinIO Bronze layer. 
- **Predicate Pushdown:** When a user searches for specific accessions (e.g., `8586`), the API pushes this filter directly to the storage layer. Only the requested Parquet partitions are loaded into memory, drastically reducing network overhead.
- **Intelligent Schema Handling:** The system automatically resolves schema drift issues between different crops (e.g., removing erroneous `(Unknown)` suffixes generated by the Videometer hardware for chickpeas) to provide a unified tabular view.
- **Browser Memory Protection:** Raw Videometer data is highly dimensional (400+ columns). To prevent browser Out-Of-Memory (OOM) crashes, the dashboard renders a safe, lightweight HTML table preview while offering the full payload securely via a CSV download button.

### 2. Morphological Visualization
- Automatically extracts core geometric features (`area`, `length`, `width`, `volume`) from the fetched Iceberg/Nessie metadata.
- Renders dynamic Plotly bar charts representing the physical profile of the selected seed accession.

### 3. MLOps & API Monitoring
- **Health Checks:** Continuously pings the FastAPI backend to verify the readiness of the Prediction API and its connection to the MLflow tracking server.
- **Zero-Downtime Hot-Swapping:** Provides a direct interface for administrators to trigger the `/reload` endpoint. If Airflow finishes training a new XGBoost or Random Forest model, clicking this button instructs the API to fetch the latest artifact from the registry without dropping active HTTP requests.

## Deployment Strategy

By decoupling the Streamlit frontend from the FastAPI backend, the architecture follows enterprise-grade deployment standards. This allows for:
- **Independent Scaling:** The API can be horizontally scaled (e.g., via Kubernetes replicas) to handle thousands of inference requests, while the Dashboard remains a single, lightweight instance.
- **Security & Sovereignty:** The entire stack, including the UI, runs completely On-Premise. Sensitive seed morphological data never leaves the internal organizational network.
